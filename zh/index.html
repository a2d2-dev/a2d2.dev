    Context 第一性原理：从大模型的物理约束推导工程架构

    你知道 prompt 要写好，知道 context 不能太长，知道输出要验证，知道多 Agent 比单 Agent 好——但这些“知道”是散落的经验，不是统一的理论。本文从四条核心约束出发：L0，Prompt 使 LLM 从弥散状态收敛到特定方向，但 context 有限，收敛有代价；L1，项目特定的知识只能通过有限的 context window 获取；L2，推理过程是无状态的，每次调用从零开始；L3，输出是概率的，不是确定的。经由桥接定理——选择性加载、上下文衰变、频率匹配持久化、后果比例验证、反馈归因——推导出一套工程架构：收敛工程、知识分层、工具与环境、会话生命周期管理、持久化栈、信任层次和反馈回路，并讨论约束之间的交叉张力。四条约束，一套架构；约束不可违反，架构可以演进。

    系统描述问题：当瓶颈从执行层转移到描述层

    人类开发者是补偿器，LLM 是条件性的放大器：输入信号有缺口时，它不会停下来说“信息不足”，而是用训练数据中最常见的统计模式填充缺口——而你不知道它在哪里做了填充。当执行者从补偿器变成放大器，输入质量成为主导约束。本文用金观涛《控制论与科学方法论》的框架，把软件开发看作缩小可能性空间的过程，把随机控制、有记忆控制、共轭控制、负反馈调节四种递进的控制方法，映射到 AI 编码的四个阶段：Vibe Coding、规则驱动、Spec 驱动和 Harness Engineering。进而推导 Spec 侧的工程方案（按变更频率分层、单元自包含、源头唯一与血缘追踪）和 Harness 侧的检测缺口（完备性、结构一致性、语义一致性），并重新定义人类的角色：维持共轭控制的两端——高质量的 L 过程和 L' 过程。

    用结构对抗不确定性：LLM 工程的控制论工具箱

    《系统描述问题》的补论。1927 年，Harold Black 在贝尔实验室没有去造更好的真空管，而是改变了系统结构，由此得到一条定理：闭环系统的整体精度主要取决于反馈通道的精度，而不是前向通道的精度。LLM 就是那个不精确的真空管。由此得到元定理——系统精度是结构的函数——及其推论：把传感器基础设施当作一等公民来投资。本文铺开控制论的完整工具箱：冗余与表决、级联控制、前馈补偿、滤波与状态估计、自适应控制、鲁棒控制，覆盖时间、空间、信息、架构、学习五个维度，逐一映射到 LLM 工程，并把“偏差能被检测到吗？”扩展为五个检查问题。大多数团队应该从反馈和前馈开始。
